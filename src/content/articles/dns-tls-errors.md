> **先看结论：**域名解析失败、无法建立连接和证书校验失败发生在不同阶段。先记录原始错误，检查时间、域名和实际路径，不要通过关闭证书验证来解决。

## 分清错误阶段

| 错误类型 | 优先检查 |
| --- | --- |
| DNS 解析失败 | 域名拼写、解析器可达性、客户端 DNS 与路由 |
| 连接超时或拒绝 | 目标端口、节点、网络路径与服务状态 |
| TLS 或证书错误 | 系统时间、访问域名、证书有效性、软件版本 |
| HTTP 错误码 | 网站应用、账号权限、限流与服务端响应 |

同一现象可能有多种原因，表格是检查顺序，不是直接诊断结论。

## DNS 问题怎样定位

先确认目标域名正确，比较普通网站和另一个接入网络。查看客户端实际使用的 DNS 配置，了解解析请求与业务请求是否走相同路径。

只有某个域名失败时，还需核对目标服务自身状态。随意更换解析器不一定改善链路，也可能改变隐私和分流行为。配置字段按所用客户端当前文档核对。

## TLS 与证书要检查什么

确认系统日期和时区准确，证书属于访问的域名，并检查是否存在门户登录、未知根证书或流量检查工具。过旧的软件和不兼容配置也可能失败。

不要安装陌生证书、关闭校验或接受不匹配证书来继续提交密码。先核实连接环境与网站身份。

## 求助记录与恢复

保留报错、时间、目标域名、软件和内核版本，以及已经做过的对照。隐藏账号、订阅、访问资料和密钥后再提供日志。

恢复到已知可用配置后，每次只改一项。更多步骤见[连接故障排查](/articles/connection-troubleshooting/)与[客户端列表](/clients/)。
